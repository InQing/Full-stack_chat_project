## 设计文档

### 总体概述
客户端使用Http将文件分片上传，并携带MD5码，服务器收到所有分片后，先校验MD5码，再合并文件，最后调用七牛云的API将文件上传到七牛云。

### 一、服务器部分

#### 1. 资源服务器的概要设计

资源服务器负责文件的上传、存储、下载等操作，并支持分片传输和流式传输。其核心功能包括：

- **文件上传接口**：支持大文件分片上传、断点续传。
- **文件下载接口**：支持按需流式传输文件或分片下载，能够提供文件的部分内容。
- **七牛云对象存储**：调用七牛云的API将文件上传到七牛云。

##### 资源服务器接口设计

| HTTP Method | 路径                | 描述         | 请求参数                                        | 返回值          |
| ----------- | ------------------- | ------------ | ----------------------------------------------- | --------------- |
| POST        | /upload             | 上传文件分片 | file_id, chunk, chunk_number, total_chunks, md5 | 200 OK/错误信息 |
| GET         | /download/{file_id} | 下载文件     | file_id                                         | 文件内容        |

#### 2. 资源服务器传输优化策略

- **分片传输**：

  - 客户端将大文件分成多个小块，逐个上传或下载。每个块的大小应根据服务器负载、网络带宽和文件大小动态调整。
  - 服务器接收到文件分片后，暂时保存每个分片并生成对应的标识（如 `file_id`），直到所有分片上传完毕。
  - 对于大文件下载，支持按分片下载，避免内存溢出和带宽占用过高。
  - **分片校验**：每个分片上传时，客户端会计算该分片的 MD5 值并一并上传。服务器接收到分片后，进行 MD5 校验以确保数据完整性。

- **流式传输**：
  - 服务器和客户端使用流式传输，避免将整个文件内容加载到内存中，提高内存使用效率，尤其是对于大文件上传和下载。
  - 流式上传时，客户端将文件按小块分批上传，而服务器则将接收到的数据流立即写入存储介质。
  - 流式下载时，服务器根据客户端请求的数据范围，按流式方式将文件内容传输给客户端，避免一次性加载整个文件到内存。

#### 3. 资源服务器的程序架构

资源服务器采用简洁的三层架构设计，结构清晰易懂：

```
/resource-server
├── /api                  # 接口层：处理 HTTP 请求
│   ├── routes.go        # 路由配置
│   ├── upload.go        # 上传接口
│   ├── download.go      # 下载接口
│   └── middleware       # 中间件
│       └── log.go       # 日志中间件
│
├── /service             # 业务层：核心业务逻辑
│   ├── upload.go        # 上传业务逻辑
│   ├── download.go      # 下载业务逻辑
│   └── storage.go       # 存储业务逻辑
│
├── /storage             # 存储层：数据存储实现
│   ├── local.go         # 本地存储
│   └── qiniu.go         # 七牛云存储，调用七牛云的API将文件上传到七牛云
│
└── main.go              # 程序入口
```

##### 分层说明

1. **接口层 (`/api`)**

   - 处理 HTTP 请求和响应
   - 参数验证和错误处理

2. **业务层 (`/service`)**

   - 实现核心业务逻辑
   - 处理文件上传和下载
   - 协调存储操作

3. **存储层 (`/storage`)**
   - 提供存储接口实现
   - 支持本地存储和七牛云存储
   - 处理具体的存储操作

### 二、客户端部分

#### 1. 客户端的概要设计

客户端负责上传和下载文件，支持分片上传、流式上传和下载，采用 Qt 框架编写。客户端通过 `QNetworkAccessManager` 发送 HTTP 请求，并将文件分片上传或下载。

##### 核心功能：

- **文件上传**：支持文件分片上传、断点续传。
- **文件下载**：支持文件分片下载，断点续传。
- **文件进度显示**：显示上传/下载进度。
- **并发上传/下载**：利用多线程实现多个文件的并发上传或下载。

#### 2. 客户端的优化策略

- **并行处理**：

  - 使用 **线程池** 技术并发处理多个文件的上传和下载操作，提高整体文件处理效率。
  - 每个文件分成多个小块上传，并通过多个线程同时处理不同文件的分片上传，避免阻塞和等待。
  - 线程池大小可以根据网络带宽和 CPU 核心数进行动态调整。

- **分片上传**：

  - 每个文件被分成多个分片，分片大小可以根据文件的大小和网络状况动态调整。每个分片上传时，不需要将整个文件加载到内存中，从而节省内存并提高传输效率。

- **流式传输**：

  - 文件上传/下载时，避免将整个文件加载到内存中，而是通过流式传输逐步上传/下载文件的每个分片。使用 Qt 的 `QHttpPart` 和 `QNetworkAccessManager` 进行流式上传/下载。

- **断点续传**：
  - 客户端在上传或下载过程中记录已传输的进度（如文件的分片号），如果上传/下载中断，可以通过记录的进度从中断位置继续。

#### 3. 客户端的核心函数

- **`uploadFile()`**：
  - **功能描述**：客户端从本地文件系统读取文件内容，将文件分成若干个小块（分片），并逐个上传每个分片。上传过程中，客户端会记录上传进度以便支持断点续传功能。客户端通过 `QNetworkAccessManager` 发起 HTTP 请求，将每个分片发送到服务器。
  - **参数**：文件路径、文件 ID、分片数、当前分片编号、MD5 校验值。
- **`downloadFile()`**：

  - **功能描述**：客户端根据文件标识符 `file_id` 请求服务器下载文件。客户端按分片接收文件内容并保存至本地磁盘，支持断点续传和流式传输。下载过程中，客户端会实时显示进度。

- **`parallelUpload()`**：

  - **功能描述**：为了提高上传效率，客户端使用线程池并行上传多个文件。每个文件会被分割成多个分片，通过线程池中的多个线程同时上传文件的不同分片。

- **`updateProgress()`**：
  - **功能描述**：在上传或下载过程中，客户端实时更新进度显示，反馈上传/下载的当前进度，帮助用户监控文件传输状态。

### 三、传输数据的 JSON 格式

**上传文件请求：**

```json
{
  "file_id": "unique_file_id_12345",
  "chunk": "base64_encoded_chunk_data",
  "chunk_number": 1,
  "total_chunks": 10,
  "md5": "d41d8cd98f00b204e9800998ecf8427e"
}
```

- `file_id`: 唯一标识文件的 ID，服务器通过该 ID 识别文件。
- `chunk`: 当前上传的文件分片数据，采用 Base64 编码。
- `chunk_number`: 当前分片的编号，从 1 开始。
- `total_chunks`: 文件总的分片数。
- `md5`: 当前分片的 MD5 校验值，用于确保分片的完整性。

**下载文件请求：**

```json
{
  "file_id": "unique_file_id_12345"
}
```

- `file_id`: 要下载的文件 ID，服务器用该 ID 查找文件并开始下载。

**上传文件响应：**

```json
{
  "status": "success",
  "message": "File chunk uploaded successfully",
  "uploaded_chunks": 3,
  "total_chunks": 10
}
```

- `status`: 上传请求的状态，成功或失败。
- `message`: 请求的详细信息。
- `uploaded_chunks`: 已上传的分片数量。
- `total_chunks`: 文件总的分片数。

**下载文件响应：**

```json
{
  "status": "success",
  "message": "File downloaded successfully",
  "file_data": "base64_encoded_file_data"
}
```

- `status`: 下载请求的状态，成功或失败。
- `message`: 请求的详细信息。
- `file_data`: 下载的文件数据，采用 Base64 编码。

### 四、总结

本设计文档描述了如何使用 **Go + Gin** 和 **Qt** 实现支持分片上传、流式传输、断点续传和 MD5 校验的资源服务器与客户端。通过分片传输和流式传输，可以有效提高文件上传和下载的效率，降低内存使用和网络带宽压力。客户端通过线程池实现并行处理多个文件，提高整体传输效率。同时，服务器通过回包返回进度信息，简化了客户端的处理逻辑。MD5 校验增强了数据完整性，确保每个分片上传过程中的可靠性。
